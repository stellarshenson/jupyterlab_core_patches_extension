# Terminal CPR escape

Filters terminal query responses that fish and other shells print as literal text in an idle terminal, keeps a terminal restored in a background tab at its real size, and reconnects a terminal whose connection JupyterLab stopped retrying. This extension is a direct replacement for the discrete `jupyterlab_terminal_cpr_escape_fix` package and for that package's entry in the `stellars_jupyterlab_fixes` bundle. Uninstall the bundle and the discrete package before installing this one, because two installed copies apply every patch twice.

The filter runs on the server, in `jupyter_server_terminals`. It removes CPR, DA, DA2, DSR, XTWINOPS, DECRQSS, kitty keyboard and OSC colour responses from live output and from a buffer replay, in both the ESC-prefixed form and the bare form that fish produces after it strips ESC. The same server patch strips terminal queries from a replay and steps the PTY size after a reattach so a full-screen program repaints. The frontend part handles a terminal restored in a background tab: it holds back the size that the unopened 80x24 xterm reports until the tab is first shown, then the widget sends the fitted size and the patch steps the PTY one column narrower and back so the running program repaints at that size. The frontend part also reconnects a terminal that a laptop sleep or a network drop left without a connection: JupyterLab retries a closed terminal websocket 7 times, then sets the session status `disconnected` and never retries, so the tab keeps its last screen and typed text waits in the session queue. The patch calls `session.reconnect()` for such a session when the page becomes visible again, when the browser fires `online`, and when the user types into that terminal; the queued text goes out after the reconnect.

The frontend part runs through the shared terminal-session module `src/fixes/terminal-session.ts`, which also serves the restore terminals patch (`docs/restore-terminals.md`). The plugin registers its part with `registerCprEscape`; the module connects one `widgetAdded` handler per page and installs one `session.send` wrapper per session that carries both the size hold and the typing reconnect. The server part reads the shell names and the `/proc` files through the shared helper `jupyterlab_core_patches_extension/server/terminal_processes.py`, which the restore terminals server module reads too.

- **Switch** - `jupyterlab_terminal_cpr_escape_fix`, boolean, default `true`. The frontend plugin reads the switch at activation, so a change applies on the next page reload. The server wrappers read the same switch on every terminal output and on every socket open, so the server half stops patching at the next call after a change
- **Plugin id** - `@stellarshenson/jupyterlab-core-patches-extension:terminal-cpr-escape`
- **Patched member** - server: `jupyter_server_terminals.handlers.TermSocket.on_pty_read` and `TermSocket.open`; frontend: the `send` method of each terminal session, wrapped once by the shared terminal-session module for both the size hold and the `stdin` watch of the reconnect, the terminal's `disposed` signal and a `MutationObserver` on the terminal node; the reconnect calls `TerminalConnection.reconnect()`, and the module listens to `visibilitychange` on `document` and `online` on `window`
- **Guard** - server: the class attribute `TermSocket._jp_terminal_cpr_escape_patched`, set by `patch_term_socket` before the wrappers are installed, makes a second call a no-op. Frontend: the `WeakSet` `wrappedSessions` of the shared terminal-session module makes a second wrap of the same session a no-op, so a session carries at most one `send` wrapper. The source frontend had no guard; without one a second call wraps `session.send` again and leaves a stale wrapper on the session after the first open restores the original. The `WeakMap` `trackers` of the same module makes a second `registerCprEscape` on the same tracker a no-op, so the `widgetAdded` handler and the two page listeners are installed once per page. At the hold's release the wrapper stays on the session for the typing reconnect
- **Source** - `jupyterlab_terminal_cpr_escape_fix` v1.0.22: `src/index.ts`, `src/unopenedTerminal.ts`, `jupyterlab_terminal_cpr_escape_fix/__init__.py`, `handlers.py` and `replay_clear.py`. The patch logic is ported with the clear-before-replay step removed; the switch gate, the settings source, the import paths and that removal are the only changes to the ported logic. The port of `src/unopenedTerminal.ts` lives in the shared `src/fixes/terminal-session.ts`. The reconnect is not in the source; this package adds it for the defect `DEF-PATCH-7-TERMINAL-INPUT`, in the same shared module
- **Jest test** - `src/__tests__/terminal-cpr-escape.spec.ts`. Ports the source's `unopenedTerminal.spec.ts` tests and adds the plugin gate, the `redrawBackgroundTerminals` option, the first-show PTY step and its skip for a new session, the second-call no-op and the double activation no-op. The reconnect tests cover the visible and online triggers, typing into a stock `TerminalConnection` that gave up with the text sent in typed order after the connection opens, the typing trigger after the hold's release, one wrapper per session, no reconnect for a connected, connecting or disposed session, one reconnect for triggers that arrive together, and no listener with the switch off. `src/__tests__/terminal-session.spec.ts` covers the shared module with both terminal plugins on one tracker: one `widgetAdded` handler and one `send` wrapper per session in either activation order, the four switch combinations, and each page listener and timer installed once. `jupyterlab_core_patches_extension/tests/test_terminal_processes.py` covers the shared server helper
- **Galata test** - `ui-tests/tests/terminal-cpr-escape.spec.ts`. Showing a terminal restored in a background tab opens one websocket with the switch off and with the switch on. The switch-on case also asserts that no `set_size` sends 80x24 and that a one-column step follows the fitted size. Two reconnect tests route the terminal websocket through the test, lower the session's retry limit from 7 to 1 and refuse the retry until the status is `disconnected`: a `visibilitychange` then brings output printed during the drop into the tab, and `echo back` typed while disconnected prints `back` after the reconnect

## Behaviour

- **Response filter** - applies to live output and to a replay; matches only responses, never queries, so capability negotiation keeps working. Removes CPR (plain and private form), DA, DA2, DSR `ESC[0n`, XTWINOPS `ESC[8;rows;colst` and `ESC[4;height;widtht`, DECRQSS replies, kitty keyboard reports, DECRPM and OSC colour responses, ESC-prefixed and bare. A byte form shared with a command (an XTWINOPS resize) is removed in both roles
- **Replay queries** - removed from a replay; when the foreground process group is one shell alone every query is removed, otherwise a run of queries that ends the replay is kept, because the program that sent that run may still wait for the answer
- **No added bytes** - an open or reconnect sends the replay unchanged apart from query stripping; the patch adds no screen clear and no alternate-screen switch. An empty buffer sends no frame
- **Repaint on attach** - sets the PTY one column narrower 0.4 s after a reattach and back 0.12 s later; at most one step per terminal per 5 s; skipped while the foreground process group is one shell alone
- **First attach** - the first attach of a terminal gets no repaint step, because the client sees the session from its start; a command the new session runs, such as one a session bookmark sends, reads the fitted size. Every later attach, the reattach after a page reload included, keeps the step. The mark is set on the terminado terminal object, so a new terminal that reuses the name of a closed one counts as new
- **Background terminal** - an unopened xterm reports 80x24; the patch drops `set_size` until the xterm opens, then the widget sends the fitted size and the patch steps the PTY one column narrower and back so the running program repaints at that size
- **New session** - a terminal whose session was not running when the page loaded, such as one the page starts new, gets the fitted size and no step
- **Reconnect** - a session in status `disconnected` that is not disposed reconnects when the page becomes visible again, when the browser fires `online`, and on a `stdin` message from that terminal. The visible and online triggers walk the terminal tracker at the event. A `connected` or `connecting` session gets no reconnect, so triggers that arrive together start one reconnect. Text typed while disconnected stays in the session queue and goes out in typed order after the connection opens. The server replays the terminal buffer at the reconnect, so output printed during the drop reaches the tab
- **Apply time** - a switch change reaches the frontend on the next page reload and the server on the next terminal output or socket open

## Server part

The module exports `patch_term_socket(server_app)` and registers no HTTP route. The integrator calls it from `_load_jupyter_server_extension`. `redrawBackgroundTerminals` gates the repaint step and is read on every attach; the other three source defaults (`suppress_buffer_replay` off, `filter_osc_color_responses` on, `strip_replay_queries` on) are fixed module constants because this package exposes no switch for them.

## Limits

- **Galata scope** - the test counts websocket opens and asserts the one-column step. It does not assert the width of the replayed history, which depends on the xterm buffer size and the shell prompt, and it does not exercise the response filter, which needs a shell that strips ESC from a CPR response (fish)
- **Repaint step** - a client resize to exactly `cols - 1` within the step window is taken for the step and reverted; the PTY is one column wider than that client until the next resize
- **First-show step** - a client resize within the 120 ms first-show step window is overwritten by the restore until the next resize
- **Line editors** - a line editor that is not one of the eight shells in `SHELL_NAMES` is still stepped; on a system without `/proc/<pid>/task/<pid>/children` the step always runs
- **Fragmented redraw** - fish redraws its command line in fragments between cursor moves, so a response split across a redraw does not match a contiguous pattern and can still reach the screen; the filter removes whole sequences only
- **Bare DSR in prose** - `BARE_DSR` matches the four characters `[0n` wherever they appear, so literal text such as `value [0n] here` comes out as `value ] here`; the bare answer carries nothing that distinguishes it from that text, so the pattern is not narrowed
- **Unopened xterm** - the hold applies only to a terminal whose xterm was never opened; a terminal already shown keeps the stock flow
- **Reconnect retries** - a reconnect starts the stock 7 retries again; when they fail too, the terminal stays `disconnected` until the next trigger. The tab keeps its old screen and the replay is written below it, as after a stock retry that succeeds
- **Online trigger** - covered by Jest only; the Galata tests fire `visibilitychange` and type, and do not toggle the browser network
